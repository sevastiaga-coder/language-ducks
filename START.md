# Как начать проект и что делать дальше

Короткая инструкция по запуску студии. Первая часть — для ребёнка, вторая — разовая настройка для родителя.

---

## 1. Завести проект

**Одна папка — один проект.** Папка `MyStudio` — это шаблон: её не трогаем, а копируем под каждый новый проект.

```bash
cd "/Users/olegkobyzev/Documents/Проекты code"
cp -R MyStudio cat-game        # cat-game — имя проекта, по-английски
```

Дальше открываем копию (`cat-game`) в VS Code и в ней запускаем чат Claude Code. Внутри копии будет свой дневник, свой план и свой репозиторий — истории проектов не перемешиваются.

---

## 2. Первое сообщение в чат

Никаких команд учить не надо. Пишем обычными словами, что хочется сделать:

> хочу игру, где надо ловить убегающего кота

Всё остальное студия спросит сама, по одному вопросу за раз.

---

## 3. Что будет дальше — пять шагов

| Шаг | Что делает студия | Что делает босс |
|-----|-------------------|-----------------|
| 1. Идея | Расспрашивает и режет идею до первой версии; сама выбирает, на чём делаем | Отвечает на вопросы, решает, что войдёт в первую версию |
| 2. Вид | Готовит три варианта оформления и открывает их в браузере | Смотрит глазами и выбирает (можно смешивать: «цвета из первого, шрифт из второго») |
| 3. План | Раскладывает работу на части и выпуски | Смотрит список, соглашается или переставляет важность |
| 4. Сборка | Пишет код, проверяет, показывает промежуточные результаты | **Проверяет руками** и говорит, что не так |
| 5. Публикация | Проверяет проект и выкладывает в интернет | Получает ссылку и скидывает друзьям |

Шаги идут по порядку, но студия ведёт сама — специально просить следующий шаг не нужно.

**Главное на шаге 4:** проект показывают в браузере после каждых 2–3 частей. Задача босса — нажимать и жаловаться. Жалоба всегда принимается: «скучно», «слишком быстро», «не понял, куда нажимать» — это самая полезная работа во всём проекте.

---

## 4. Каждый день: три фразы

| Пишем | Что произойдёт |
|-------|----------------|
| «что дальше» / `/status` | Студия прочитает дневник и напомнит, где остановились |
| «не работает кнопка» / `/fix` | Починит или переделает так, как хочется |
| «что я уже знаю» / `/words` | Покажет словарик освоенных слов |

**Начало новой сессии** (вернулись через неделю): просто написать «что дальше». Помнить ничего не надо — за это отвечают файлы в `studio/`.

**Продолжить сборку:** «поехали», «давай дальше», «продолжаем».

---

## 5. Где что лежит

```
studio/idea.md        что за проект, для кого, что в первой версии
studio/style.md       цвета, шрифты, экраны
studio/plan.md        части и выпуски: что готово, что сломано
studio/diary.md       где мы сейчас + история решений
studio/words.md       словарик босса
studio/for-parent.md  записки родителю
app/                  сам проект, код
```

Заглядывать можно в любой момент — там записано, что решили и почему.

## 6. Разовая настройка для родителя

Нужна **один раз на все будущие проекты**, до первой публикации. Пока не сделана — проект спокойно живёт на компьютере, публикация просто откладывается.

**Сейчас не установлен `gh` — инструмент для работы с GitHub из терминала.** Установка:

```bash
brew install gh     # если нет Homebrew — https://brew.sh
gh auth login       # выбрать GitHub.com → HTTPS → войти через браузер
```

Проверка, что всё получилось:

```bash
gh auth status      # должно написать "Logged in to github.com"
```

Ещё понадобится аккаунт GitHub — заводится там же, в процессе входа.

---

## 7. Когда студия позовёт родителя

Она останавливается и оставляет записку в `studio/for-parent.md`, если проекту нужен сервер или база, платный ключ к внешнему сервису, логины и пароли пользователей, новый аккаунт или общение с незнакомыми людьми (чат, комментарии).

Ребёнок при этом не ждёт: студия всегда предлагает вариант, который работает уже сегодня (например, рекорды сохраняются в его браузере вместо общей таблицы).

---

## 8. Про публикацию — что важно знать заранее

- Репозиторий **публичный**: проект видит весь интернет. Перед публикацией отдельная проверка ищет фамилию, школу, адрес, телефон, почту и ключи — найдёт, публикация остановится.
- Имя в проекте — решение ребёнка, но лучше игровое.
- Веб-проекты выкладываются на GitHub Pages бесплатно, получается живая ссылка.
- Python-проекты ссылкой не открываются — их можно только скачать и запустить. Студия предупредит об этом заранее, на шаге идеи.
- Ничего не пропадает: даже если результат не понравился, старая версия остаётся в истории проекта.

---

## 9. Если что-то пошло не так

| Ситуация | Что делать |
|----------|-----------|
| Студия начала не с того шага | Написать прямо: «давай сначала про идею» или `/idea` |
| Ребёнок не помнит, где остановились | «что дальше» |
| Проект сломался после правки | «не работает» + что нажимал |
| Хочется начать другой проект | Скопировать `MyStudio` заново под новым именем (шаг 1) |
| Публикация не проходит | Скорее всего не сделана настройка из раздела 6 |
