# Стек-паки — память студии

Пак — это инструкция для разработчика: на чём делаем, как раскладываем файлы, как запускаем, на чём уже обжигались. Пак выбирает CTO на шаге `/idea` и фиксирует в разделе «Проект» файла CLAUDE.md. Исполнители читают пак перед работой.

## Какие есть

| Пак | Для чего |
|-----|----------|
| stack-web.md | **По умолчанию.** Сайты, игры, викторины — всё, что открывается в браузере и делится ссылкой |
| stack-python.md | Вычисления, файлы, боты, игры в окне. Ссылкой не поделишься |
| advanced/ | Взрослые стеки с сервером и базой. Только когда родитель подключил Railway |

## Правило выбора

Простое побеждает. Каждая установка, сборка и библиотека — это место, где всё сломается, а ребёнок не сможет починить сам и потеряет интерес. Если задача решается одним HTML-файлом — она решается одним HTML-файлом.

`advanced/` не трогаем без родителя: этим проектам нужен сервер, а сервер подключает взрослый.

## Грабли — зачем они

Раздел «Грабли» в каждом паке — накопительная память студии. Наступили на что-то в проекте — дописали абзац с датой, и в следующих проектах этих граблей уже не будет.

Пишем только реальные случаи: **дата, что случилось, как избегать**. Теоретические советы («лучше использовать const») туда не пишем — они и так есть в интернете.

После каждого законченного проекта CTO спрашивает себя: что из этого стоит записать в пак?

## Формат пака

```markdown
# Стек: <название>
## Когда выбирать      ← подходит / не подходит, чем берёт
## Состав              ← что используем и чего не используем
## Структура проекта   ← дерево файлов
## Конвенции           ← имена, стиль, обязательные правила
## Команды             ← запустить, проверить
## Публикация          ← как выкладывается, что с ссылкой
## Грабли              ← реальные случаи с датами
```
